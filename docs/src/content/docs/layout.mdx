Page layout is the consuming site's job. The package ships only the parts whose
behavior is worth writing once: the scroll and snap of a rail, the full-bleed
arithmetic of a band, the pager on a table. None of them needs to know what it
is carrying.

## Showcase carousel

Use it for a larger peer set where showing every item at once would dominate
the page. Controls stay minimal and native horizontal scrolling stays
available.

The rail never sees its cards' data. `tabs` is one label per card in slot
order, and the script matches a tab to a card by position among the track's
children. Slot whatever card you like; the rail sizes it.

<ShowcaseCarousel tabs={['Compile', 'Profile', 'Deploy']}>
  <Card>
    <CardMedia ratio="16/9">
      <Media
        treatment="color-field"
        style="--accent: var(--helia-accent-purple)"
      />
    </CardMedia>
    <CardHeader titleAs="h3" eyebrow="Step one">
      <span>Compile the model</span>
    </CardHeader>
    <CardContent>
      The feature variant leads with a large media block and sets the text below
      it, so use it where the carousel is the main event on the page.
    </CardContent>
  </Card>
  <Card>
    <CardMedia ratio="16/9">
      <Media treatment="slate" />
    </CardMedia>
    <CardHeader titleAs="h3" eyebrow="Step two">
      <span>Measure what it costs</span>
    </CardHeader>
    <CardContent>
      Cards are about three quarters of the track width, so the next one is
      always visible at its edge.
    </CardContent>
  </Card>
  <Card>

      active tab follows the first card at or past the visible left edge.
    </CardContent>
  </Card>
</ShowcaseCarousel>

## The compact variant

`variant="compact"` is text-forward. The whole card is one bordered surface,
the media becomes a short band at the top, and cards drop to about a third of
the width so three read at once on a desktop viewport. Use it for update feeds
and other secondary sections.

<ShowcaseCarousel
  tabs={['Runtime', 'Compiler', 'Profiler', 'Kits']}
  variant="compact"

## Sizing is the rail's

The track sets `--carousel-card-basis` and applies the flex basis and the
scroll-snap alignment to its own children, so a slotted card needs no carousel
knowledge at all. A card that wants a different width can still set its own
`flex` and win on specificity.

## Section header

Use it for the heading of a page section: the label, the title, the line under
it, and the link to the fuller view, all on one baseline. Everything is a prop
because the trailing link is aligned against the title block, which only works
if the header knows both.

<SectionHeader
  eyebrow="Ecosystem"
  title="Reference designs"
  description="Boards, sensors, and the models that have been measured on them."
  href="#section-header"
  linkLabel="View all"
/>

## Editorial band

Use it for a change of ground partway down a long page. The band escapes the
content column so the paint reaches the viewport edges, while the text inside it
stays on the readable measure. Consecutive bands butt together rather than
stacking a gap.

<EditorialBand tone="paper">
  The band is the one part that deliberately breaks out of its container. Give
  it an `id` where a nav or a deep link has to reach the section.
</EditorialBand>

## Data table

Use it for a set of values that has to be read across rows. Cells are strings:
the pager hides rows by index and the frame sizes columns from their text, and
neither survives arbitrary markup. `pageSize` is the only behavior, and it is
progressive, so every row is in the document without scripting.
