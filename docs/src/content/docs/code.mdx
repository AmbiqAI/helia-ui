Code samples should be easy to scan, copy, and compare. Keep labels useful,
highlight only the lines that require attention, and avoid decorative editor
chrome.

## File example

Use a filename when the sample belongs in a specific project location. Line
numbers and highlights are optional.

<CodeBlock
  filename="src/measurements.ts"
  language="typescript"
  lineNumbers
  highlightLines={[4, 5]}
  code={`const samples = [5.2, 4.8, 5.0, 4.9];

export function averageLatency(values: number[]) {
  const total = values.reduce((sum, value) => sum + value, 0);
  return total / values.length;
}`}
/>

## Bare snippet

Use the bare variant for short, self-contained examples that do not need a
filename, terminal context, or language switcher.

<CodeBlock
  variant="bare"
  language="typescript"
  code={`const measurements = {
  latencyMs: 4.8,
  peakMemoryKb: 184,
};

console.log(measurements);`}
/>

## Language tabs

Use tabs for equivalent implementations. Do not hide unrelated steps or
materially different workflows behind language selection.

<CodeTabs
  ariaLabel="Average latency implementation"
  tabs={[
    {
      label: 'TypeScript',
      language: 'typescript',
      code: `const average = values.reduce((sum, value) => sum + value, 0) / values.length;`,
    },
    {
      label: 'Python',
      language: 'python',
      code: `average = sum(values) / len(values)`,
    },
    {
      label: 'C',
      language: 'c',
      code: `float average = total / (float)sample_count;`,
    },
  ]}
/>

## ASCII terminal

`AsciiTerminal` renders a command-and-output transcript as markup. Give it
`lines`; a `command` line gets a prompt, every other kind is output. The default
form ships no JavaScript at all, which makes it the right choice for reference
transcripts and for ASCII diagrams that need a monospace grid.

<AsciiTerminal
  title="Expected output"
  lines={[
    { kind: 'command', text: 'npm run build' },
    { kind: 'muted', text: 'Resolving configuration…' },
    { kind: 'output', text: '' },
    { kind: 'output', text: '  ENTRY     src/index.ts' },
    { kind: 'output', text: '  TARGET    es2022' },
    { kind: 'output', text: '' },
    { kind: 'success', text: '✓ Build complete' },
  ]}
/>

Spaces are preserved and the viewport scrolls horizontally rather than wrapping,
so the component also holds a diagram that has to keep its columns.

<AsciiTerminal
  title="Build path"
  tone="light"
  lines={[
    { text: 'source' },
    { text: '     │' },
    { text: '     ▼' },
    { text: 'compiler ──▶ bundle ──▶ artifact' },
  ]}
/>

Add `animated` when watching a short sequence unfold is part of the
explanation. Commands then type character by character and output arrives a line
at a time, with replay as an explicit control. `copy` adds a clipboard action
for the whole transcript. Either option makes the component emit its behaviour
script, so ask for them deliberately.

<AsciiTerminal
  title="First run"
  animated
  copy
  tone="dark"
  lines={[
    { kind: 'command', text: 'npx create-thing my-app' },
    { kind: 'muted', text: 'Fetching template…' },
    { kind: 'output', text: '' },
    { kind: 'output', text: '  CREATED   my-app/' },
    { kind: 'warning', text: '  ! remember to set an accent colour' },
    { kind: 'output', text: '' },
    { kind: 'success', text: '✓ Ready' },
  ]}
/>

`tone` decides which way round the transcript reads. `adaptive`, the default,
follows the page theme. `light` is dark ink on a fixed pale backdrop and `dark`
is pale ink on a fixed dark one; both keep their palette when the reader
switches themes, which is what you want for a screenshot-like transcript sitting
in a light page.

Under `prefers-reduced-motion: reduce` the complete transcript is shown at once
and the caret does not blink, whether or not the reader had already started an
animation. The `<pre>` is hidden from assistive technology and a visually hidden
copy of the transcript carries the reading order, so a partially typed line is
never announced.

### Authoring guidance

- Animate one short sequence, not a long live log.
- Use `command` lines for what the reader types and output lines for responses.
- Keep measured performance claims out of illustrative transcripts.
- Prefer the static form for output a reader needs to scan quickly.

## What the parts cover

- Copyable code and terminal blocks
- Bare snippets with a floating copy action
- Filename and language context
- Optional line numbers and highlights
- Keyboard-accessible language tabs
- Diff presentation
- Static and animated terminal transcripts

`CodeBlock` and `CodeTabs` render through Shiki at build time, so a page pays no
JavaScript for highlighting; their copy button is the only script either one
ships. `AsciiTerminal` is not highlighted at all and ships nothing unless asked.
