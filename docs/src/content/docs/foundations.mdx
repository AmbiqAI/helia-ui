Three stylesheets carry the vocabulary. `tokens.css` holds the primitives for
both themes and maps them onto Starlight's `--sl-*` variables. `semantic.css`
names the steps that authoring uses: spacing, radius, type, weight, leading,
ink, surfaces, tones, accents. `recipes.css` turns those into the shapes the
parts share.

They are unlayered on purpose, so they outrank every cascade layer a Tailwind
entry declares. That is what keeps a token authoritative over whatever the
Starlight Tailwind compat package wires up underneath.

## Spacing

One scale, six steps and a hairline. A part that takes a spacing prop names a
step rather than a length, so the same value reaches the part, the recipe, and
the Tailwind utility.

The Tailwind entry maps each step onto `--spacing-*`, so `p-3` and
`padding: var(--helia-space-3)` are the same value by construction rather than
by convention.

## Accents

The accent set is the package's whole colour vocabulary. There are no product
names here: a consuming site maps its own subjects onto an accent in the
composition that knows what they mean, and hands it to a part as `--accent`.

<Callout tone="note" title="Accent is a custom property, not a prop">
  `Media` takes its colour as `style="--accent: var(--helia-accent-cyan)"`
  rather than `accent="cyan"`. That is deliberate: a prop would be an
  enumeration the package has to own, and owning it would mean owning what each
  name is for. As a custom property the part never learns the vocabulary.
</Callout>

## Typography

Use the native system sans stack for interface and editorial copy, and the
native monospace stack for code, filenames, versions, and machine-oriented
identifiers. Choose a named role before introducing a local size or weight.

## The Ambiq wordmark

The plugin's footer renders the approved Ambiq wordmark, and the component is
available on its own at `@ambiqai/helia-ui/starlight/AmbiqLogo.astro`. It keeps
the source artwork intact while exposing only the three approved treatments.
